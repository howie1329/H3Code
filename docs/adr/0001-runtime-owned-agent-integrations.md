# Use provider-specific runtime integrations

H3Code integrates coding-agent runtimes such as Pi, Codex, and Claude Code through the strongest native boundary each runtime provides rather than integrating model providers or owning an agent loop. For Pi, H3Code follows BB's provider-specific bridge pattern: a dedicated Node process hosts a pinned Pi SDK, loads the user's normal Pi configuration and resources, and translates native commands and events into H3Code's Thread contract. `@ai-sdk/harness-pi` is not used because its sandbox and resource policies do not preserve the required local Pi behavior. Every Thread has exactly one canonical runtime session owner. H3Code-created Pi sessions use deterministic H3Code-owned paths; terminal-created Pi sessions may be imported by reference at their native paths.
